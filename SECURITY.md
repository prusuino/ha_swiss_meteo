# Security Policy

## Supported Versions

Only the latest release is supported. Please update to the latest version before reporting an issue.

## Reporting a Vulnerability

This integration only reads public files from one Swiss federal data service and the public MeteoAlarm warning feed over HTTPS. It has no credentials, no write access to any external system and no third-party dependencies. One optional part, off by default, additionally reads modelled values from Open-Meteo and sends the coordinates of the forecast point there; it is described separately below.

**What it sends:** every request goes to `https://data.geo.admin.ch` (the federal geodata platform that hosts the MeteoSwiss open data) over TLS: HEAD and range (`Range: bytes=…`) requests for the forecast files of the model run (and, when the HEAD probe finds no run, one GET of the collection's STAC item list), GET requests for the station's 10-minute file, the pollen station's hourly file and (with the radar nowcast on) the newest radar composite (30 to 160 KB) every five minutes, the station's archive files (up to 7 MB each) when you run the history-import action, the station's daily archive (once, up to 7 MB, for the climate figures; afterwards a HEAD request every 30 days, daily in the new year until last year has been added) and its daily values of the current year every three hours, for the Switzerland card — only while it is open — the three daily forecast files of the whole country (at most every three hours) and the radar composites of the last hour, and — at setup and in the Configure dialog — the lists of forecast points, weather stations and pollen stations. The URLs carry the run time, the parameter name and the station abbreviations. With official warnings on, one GET every ten minutes fetches `https://feeds.meteoalarm.org/api/v1/warnings/feeds-switzerland` (EUMETNET's public CAP feed for the whole country, no parameters). **With the Open-Meteo option off (the default), your coordinates never leave your instance:** the nearest point and station are chosen locally from the downloaded lists, the forecast is read by the point's id, and the warnings are matched to the point locally against the polygons in the feed. No account, cookie or key is involved; the user agent names this integration. The radar card, when its background map is on (the default), makes your **browser** load map tiles from `https://wmts.geo.admin.ch` (swisstopo, no key); the tile coordinates reveal the 200 km area shown, not your point. Set `basemap: none` on the card to keep the browser's requests to your Home Assistant instance only. The Switzerland card makes your browser load relief tiles from the same service; they show the part of Switzerland you are looking at. Set `show_relief: false` to load none. Its avalanche, alert, forest fire, flood and drought layers ask only your own Home Assistant instance for what the Swiss Avalanche Bulletin and Swiss Public Alerts integrations already hold.

**The warnings** (switch *Official warnings*, on by default): requests go to `https://feeds.meteoalarm.org` over TLS: every ten minutes a HEAD for the length of the Atom feed of the Swiss alerts in force, a GET of that feed when its length changed and at least once an hour, and one GET for each alert whose area contains the forecast point, once per alert. The requests carry no location: the feed lists every Swiss alert, and which of them cover the point is decided inside Home Assistant.

**The optional Open-Meteo part** (switch *Air quality, UV index and pollen forecast from Open-Meteo* in the setup and in the Configure dialog, **off by default**): while it is off, no request goes to Open-Meteo. With it on, one GET an hour goes to `https://air-quality-api.open-meteo.com/v1/air-quality` over TLS. The query carries the latitude and longitude of the chosen **forecast point** (the MeteoSwiss point of the postal code or station you picked, not your Home Assistant location), rounded to two decimals (about a kilometre), the names of the requested series, the number of forecast days and the fixed time zone `Europe/Zurich`. No account, cookie or key is involved; the user agent names this integration and its version. Open-Meteo is a third party outside Switzerland's federal data services, so its operator sees your instance's IP address together with those rounded coordinates. Switching the option off stops the requests and removes the device and its sensors.

**What it stores:** the chosen point, weather station and pollen station, their names and coordinates, and the options, in Home Assistant's config entries; the history import writes statistics into the recorder database. The integration also keeps, per entry, where the forecast point stands in the forecast files (byte offsets per parameter and the number of the point) in `.storage/swiss_meteo.hints_<entry id>`, so that the next run is read at the known place, and the table made from the station's archive (normals and records per calendar day, yearly means, monthly precipitation normals, the season's first frost and snow, the station's abbreviation) in `.storage/swiss_meteo.climate_<entry id>`; both files are removed with the entry. The diagnostics download redacts the coordinates and altitude of the point, its name and number, the abbreviations and names of the chosen stations and the entry's title and unique id.

**Parsing:** the files are CSV; only the rows of the configured point, of your station and of the places on the Switzerland card are used, split on `;` and converted to numbers. The warning feed and the alerts are XML (Atom and CAP), parsed with the standard library's ElementTree, which does not fetch external entities; their texts are shown as attributes and in the cards as text (escaped), never rendered as HTML. The Open-Meteo answer is JSON as well; only its hourly number series are read and converted to numbers, no text from it is shown. Nothing from a file is executed or rendered as HTML, and nothing of its content is written to disk except numbers and dates (the remembered file positions and the climate table). The bundled dashboard card escapes every value it prints.

If you believe you have found a security issue, please report it privately via [GitHub Security Advisories](../../security/advisories/new) rather than opening a public issue. For anything else, please use the regular [Issues](../../issues) tab.
